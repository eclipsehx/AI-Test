**0.1 内核参数 `/etc/sysctl.conf`** `[ROOT]`：
```bash

ls -l /etc/sysctl.d/99-sysctl.conf   # 若输出含 → /etc/sysctl.conf，即软链：往 sysctl.conf 追加即两边同步，无需再动 sysctl.d；若为独立文件 ★，则再照下面也对它追加同样一行
cp /etc/sysctl.conf /etc/sysctl.conf.bak.$(date +%Y%m%d)
grep -q 'vm.max_map_count=655360' /etc/sysctl.conf || \
  echo 'vm.max_map_count=655360' >> /etc/sysctl.conf   # 对齐生产 655360，ES 硬性要求 ≥262144（grep -q 判重，防重复追加多行）
# 若 ★ 为独立文件（非软链）：启动时 systemd-sysctl 会再单独加载 sysctl.d/*.conf，只追 sysctl.conf 就漏一半 → 这条也对它补同一行（同样判重）。软链情形两边同实、自动同步，本行自然跳过。
[ -e /etc/sysctl.d/99-sysctl.conf ] && ! [ -L /etc/sysctl.d/99-sysctl.conf ] && { grep -q 'vm.max_map_count=655360' /etc/sysctl.d/99-sysctl.conf || echo 'vm.max_map_count=655360' >> /etc/sysctl.d/99-sysctl.conf; }
sysctl -p
```

**0.3 独立盘建 /data（LVM vg1/lv1，逐字对齐生产）** `[ROOT]`：
> 单块盘即可复刻生产结构：`pvcreate → vgcreate vg1 → lvcreate lv1(整盘) → mkfs.xfs`。后续再加盘可 `vgextend vg1` 扩容。
> ⚠️ **本步唯一不可逆操作**：① 的 `parted mklabel gpt` 会**立即清空目标盘的分区表与全部数据，无法撤销**。0️⃣ 断言先核设备存在/容量档/裸盘，任一不满足即 `exit 1`，绝不进 ①；满足则打印确认并留 5 秒 Ctrl-C 反悔。**核心原则：`DISK=` 是全块唯一手改的盘符，0️⃣~⑤ 全部走 `$DISK`/`$PART`——断言的盘就是毁的盘，不存在"校验 A 盘、毁 B 盘"。** 换机复用（如生产国产化机盘序变、或换 NVMe）**只改开头 `DISK=` 那一行**，后面 `parted "$DISK"`、`pvcreate "$PART"` 自动跟着走。整块包子 shell：块内 `exit 1` 仅退本块、不踢当前登录会话（同 7.2）。若中途失败须重跑，先清盘上已留的 LVM 签名（否则 0️⃣ 误判"已有文件系统"拦住）：`vgremove -f vg1; pvremove "$PART"; wipefs -a "$DISK"`（破坏性，仅失败后目标盘重建用）。
```bash
(
set -eo pipefail   # fail-fast：②~⑤ 任一非 0（pvcreate/vgcreate/lvcreate/mkfs/mount 等）立即中止本块，勿带着已污染状态往下跑一串错。pipefail：让 PART=$(lsblk | sed) 里 lsblk 上游的非 0 也能穿透（否则管道退出码取尾命令 sed、恒 0，lsblk 失败时下方 || 不触发、只留空串）被下方 || 捕获。0️⃣ 断言与 ④ 的 grep 判重均已带 || / && 兜底，不受 set -e/-o pipefail 影响；整块包子 shell → 中止只退本块、不踢会话
# 0️⃣ 硬闸断言（不可逆操作前必过，失败即中止。DISK 是全块唯一要手改的盘符，别处不许出现裸盘名）
DISK=/dev/vdb
SIZE=$(lsblk -bdno SIZE "$DISK" 2>/dev/null) || { echo "!! $DISK 不存在，停手核对 lsblk"; exit 1; }
[ "$SIZE" -gt 50000000000 ] && [ "$SIZE" -lt 200000000000 ] || { echo "!! $DISK 容量 ${SIZE}B 不在 100G 档，停手"; exit 1; }
lsblk -nrpo FSTYPE,MOUNTPOINT "$DISK" | grep -q '[^[:space:]]' && { echo "!! $DISK 已有文件系统或已挂载，停手"; exit 1; }
echo "确认 $DISK（$((SIZE/1024/1024/1024))G）为裸盘，即将清空分区表，5 秒内 Ctrl-C 取消"; sleep 5
# ① 给新盘建分区（对齐生产 PV 在分区上）。partprobe 让内核重扫，确保分区设备立即可见
parted "$DISK" --script mklabel gpt
parted "$DISK" --script mkpart primary xfs 0% 100%
partprobe "$DISK"   # set -e 下若失败（分区表未被内核采纳）即停，不继续
udevadm settle      # 等内核把分区设备节点落到位，再往下定位
# 定位真正建出的分区设备并判空。关键：必须带 -l（list，去树形前缀，否则取到 └─vdb1 而非 vdb1）+ -p（全路径，省拼 /dev/）。
# vd→/dev/vdb1、NVMe→/dev/nvme0n1p1 自动兼容；找不到/节点未建即「毁完也不续建」，绝不停在 LVM 半途。
PART=$(lsblk -nlpo NAME "$DISK" | sed -n '2p') || { echo "!! lsblk 取分区失败，停手（先再跑一次 partprobe 后重跑本块）"; exit 1; }
[ -n "$PART" ] && [ -b "$PART" ] || { echo "!! 未找到 $DISK 的分区设备，停手（先再跑一次 partprobe 后重跑本块）"; exit 1; }
echo "分区: $PART"
# ② 建 LVM：PV → VG vg1 → LV lv1（整盘 100%FREE，容量随盘），对齐生产命名
pvcreate "$PART"
vgcreate vg1 "$PART"
lvcreate -n lv1 -l 100%FREE vg1
# ③ 格式化为 xfs（对齐生产 fstype）
mkfs.xfs /dev/vg1/lv1
# ④ fstab 开机持久挂载（备份 + 判重防重复行），对齐生产 fstab 写法
cp /etc/fstab /etc/fstab.bak.$(date +%Y%m%d)
grep -q '/dev/vg1/lv1 /data' /etc/fstab || echo '/dev/vg1/lv1 /data xfs defaults 0 0' >> /etc/fstab
mkdir -p /data
mount /data   # 只挂 /data；勿用 mount -a（会把 fstab 其它未挂载项也带上，若有坏条目返回非 0，被误判成本步失败）
df -h /data   # 期望新盘容量、xfs、Filesystem=/dev/mapper/vg1-lv1
# ⑤ 建 ES data/logs 目录，属主 idp（root 建、chown 后交 idp）
mkdir -p /data/elastic/elasticsearch/{data,logs}
chown -R idp:idp /data/elastic/elasticsearch
)
```

### Step 3 — 生成并分发证书 `[idp]`

在一台机（node-1）生成两个 p12，再分发到 node-2/node-3。产物在本目录：

**3.1 生成集群 CA** `[idp]`：
```bash
cd /home/idp/elastic/elasticsearch/elasticsearch-7.17.6
export ES_JAVA_HOME=/home/idp/app/java/jdk1.8.0_301   # 强制 certutil 用与 ES 加载侧同款 JDK8（否则默认解析到包内置 JDK17，生成 p12 的算法/加密在 JDK8 加载有兼容变量；生产同组合虽能跑，同 JDK 零成本消除）
mkdir -p config/certs
bin/elasticsearch-certutil ca --days 3650 --out config/certs/ca.p12
```
> 含私钥的敏感文件，直接落目的目录 `config/certs/`，勿留在 ES_HOME 根。`--days 3650`：CA 须与叶子证书同年限，否则链条被 CA 到期截断，"10年"不成立（CA 缺省仅 1095 天=3 年）。命令执行中会让设一个 CA 密码——这就是 3.2 里 `--ca-pass` 要填的密码，**务必记住**。

**3.2 生成 transport 证书** `[idp]`：
```bash
cd /home/idp/elastic/elasticsearch/elasticsearch-7.17.6
export ES_JAVA_HOME=/home/idp/app/java/jdk1.8.0_301   # 同 3.1：certutil 与 ES 同 JDK 生成/加载
bin/elasticsearch-certutil cert \
  --ca config/certs/ca.p12 --ca-pass <3.1设的CA密码> \
  --name idp-transport \
  --dns idp-es-node-1,idp-es-node-2,idp-es-node-3 \
  --ip 10.74.20.228,10.74.20.229,10.74.20.230 \
  --days 3650 \
  --pass "" \
  --out config/certs/transport.p12
```
> 一个共享 `transport.p12`，三节点 IP/名全部放进 SAN。`--dns`/`--ip` 是"逗号分隔列表"，须在一个参数内逗号合并，勿拆成多个重复参数（否则可能只留最后一个）。`--pass ""` 让 p12 无密码 → yml 无需配 `*.ssl.keystore/truststore.secure_password`（否则三台都要 add 同一密码）。`--days 3650` 显式定有效期 10 年（省略默认仅 1095 天=3 年）。

**3.3 生成 http 证书** `[idp]`：
```bash

  --ca config/certs/ca.p12 --ca-pass <3.1设的CA密码> \
  --name idp-http \
  --dns idp-es-node-1,idp-es-node-2,idp-es-node-3 \
  --ip 10.74.20.228,10.74.20.229,10.74.20.230 \
  --days 3650 \
  --pass "" \
  --out config/certs/http.p12
```
> 一个共享 `http.p12`，含三节点 IP+DNS SAN，配合 `http.ssl`。**必须带 `--dns`**：`http.ssl.verification_mode` 默认 `full`，应用若用主机名连 https://10007 会校验证书 hostname——缺 DNS SAN 必失败；补上后 IP 连或主机名连都可（与 3.2 transport 对称）。`--ca-pass` 同上，`--pass ""` 无密码，`--days 3650` 同 3.2。

### Step 7 — 清理 cluster.initial_master_nodes + 滚动重启 `[idp]`（三台）

`cluster.initial_master_nodes` 启动时读入，**仅在本节点无既有集群状态且发现不了已有 master（bootstrap 引导场景）时才用它选主**。集群成型后若仍保留，某次整体重启时 master 不可达可能被误判为新集群、**另起一个新集群**（分裂、可能丢数据），官方规范要求成型后移除。三台注释 + 逐台滚动重启，让运行态与文件一致并验证不脑裂。

**7.0 前置：确认集群 green** `[idp]`：
```bash
# 滚动重启前先确认集群 green；若已 yellow/red，逐台停机只会放大，先按 Step 6 定位修复再重启。

curl --insecure -u 'elastic:<新密码>' "https://10.74.20.228:10007/_cat/nodes?h=ip"
#   预期恰好 3 行纯 IP（10.74.20.228/.229/.230），无 `ip` 表头；否则停手排查，勿进 7.2
```

**7.1 三台各注释掉 cluster.initial_master_nodes 行** `[idp]`（每台执行一次）：
```bash

```

**7.2 逐台滚动重启（一台一台来，顺序 node-1→2→3）** `[idp]`：
> **为什么要整体一次性粘贴、不拆开**：滚动重启是"停→确认掉出→确认进程退出→重启→待回 3 台"的严格顺序状态机，靠块内局部变量（`SELF_IP`/`QUERY_IP`/`ok`）串起来，任一阶段失败须 `exit 1` 立即中止整台、勿继续下一台——拆成独立块会丢变量、破坏中止语义。
> `QUERY_IP` 自动派生"集群中非本机的一台在线节点"，勿用本机（本机正停）；误查本机 → curl 全失败 → "掉出"假通过、回 3 永不成立 → 撞上 fail-closed 中止。整体包在子 shell：块内 `exit 1` 仅退本块，不关当前 SSH/堡垒机会话。
```bash
(
cd /home/idp/elastic/elasticsearch/elasticsearch-7.17.6
SELF_IP=$(grep -m1 '^network.host' config/elasticsearch.yml | awk '{print $2}')
QUERY_IP=$(for i in 10.74.20.228 10.74.20.229 10.74.20.230; do [ "$i" != "$SELF_IP" ] && { echo "$i"; break; }; done)
pkill -F pid            # 发起优雅关闭（只发信号即返回）
# ① 先等本机真正掉出集群（_cat/nodes 从 3 掉到 2），带 90s 上限。
#    判"掉出"须响应非空：curl 失败输出 0 行，0≤2 会把"查询失败"误判成"已掉出"。到点未确认 → fail-closed 中止。
ok=""; for i in $(seq 18); do
  out=$(curl -s --insecure -u 'elastic:<新密码>' "https://${QUERY_IP}:10007/_cat/nodes?h=ip")
  n=$(printf '%s' "$out" | grep -c .)   # 数非空行。勿用 wc -l：$( ) 剥尾换行 → 常少数 1 → 3 台在位也数成 2 → -le 2 假通过
  [ -n "$out" ] && [ "$n" -le 2 ] && { ok=1; break; }; sleep 5
done
[ -n "$ok" ] || { echo "90s 内未确认掉出（或查询失败）：中止滚动重启，勿继续停下一台"; exit 1; }
# ①b 确认本机进程已真退出才启动——掉出集群（master 视角）≠ 进程退完；未退净抢 data 目录锁失败（启动报 failed to obtain node locks）
for i in $(seq 12); do ! ps -p "$(cat pid 2>/dev/null)" >/dev/null 2>&1 && break; sleep 1; done
ps -p "$(cat pid 2>/dev/null)" >/dev/null 2>&1 && { echo "12s 内进程未退出，中止滚动重启（防未退净抢 data 目录锁）"; exit 1; }
# ② 确认掉出且进程退出后，再重启本机
export ES_JAVA_HOME=/home/idp/app/java/jdk1.8.0_301
bin/elasticsearch -d -p pid
# ③ 等回 3 台且集群回 green（入集群约 30~90s + shard reroute），带 180s 上限；超时未满足即 fail-closed 中止，勿继续下一台。
#    只等"节点数回 3"不够：本机加入后 shard 还在 reroute 时节点已计 3、health 可能仍 yellow，此时就放行停下一台，与 7.0"必须 green 才滚"口径打架。故 ③ 并上 status=green。
ok=""; for i in $(seq 36); do
  n=$(curl -s --insecure -u 'elastic:<新密码>' "https://${QUERY_IP}:10007/_cat/nodes?h=ip" | grep -c .)
  st=$(curl -s --insecure -u 'elastic:<新密码>' "https://${QUERY_IP}:10007/_cat/health?h=status")
  [ "$n" -ge 3 ] && [ "$st" = "green" ] && { ok=1; break; }; sleep 5
done
[ -n "$ok" ] || { echo "180s 未回 3 台且 green：中止滚动重启，勿继续下一台"; exit 1; }
echo "本台（$SELF_IP）滚动重启成功：进程已停 → 已掉出集群 → 已重启 → 集群回 3 台且 green；可继续下一台（顺序 node-1→2→3）"
)   # 子 shell 结束：块内 exit 1 仅终止本块，SSH 会话/堡垒机连接保留
```
> 勿同停 ≥2 台。观察日志 `master node changed` / 集群刷出该节点即加入成功；此步可顺带实测"重启不脑裂"。

## 运维说明：重启 / 停止 / 高可用

**选主时机**：仅首次建集群（Step 5）需 `initial_master_nodes` 候选中 **≥2 台在线**才能选出 master；集群成型（Step 7 清掉该行）后日常重启顺序无关。

**重启**：集群成型后日常重启无时序要求、顺序无关。逐台「停止→维护→启动」走一遍即可（启动命令见 Step 5，滚动重启全流程见 Step 7）；每台启动后看日志出现 `master node changed` / 节点被集群刷出，即加入成功。**勿同停 ≥2 台**，跌破 quorum 会停服（见下方脑裂）。

**停止**：`pkill -F pid` 读 pid 文件发 SIGTERM 触发优雅关闭（ES tar 无 `elasticsearch-stop`，等价 `kill $(cat pid)`）。只发信号、**不等进程退出**；若停止后要接着重启（如滚动重启），先轮询等进程退出再操作（"停"侧 <10s；与启动"入集群 30~90s"是两段独立时间）：
```bash
cd /home/idp/elastic/elasticsearch/elasticsearch-7.17.6
pkill -F pid
until ! ps -p $(cat pid) >/dev/null 2>&1; do sleep 1; done   # 进程退出即停（此处为交互维护、无时限版；滚动重启内 7.2 ①b 用 12s 有界 + fail-closed，两者是故意不同、勿互抄）
```

**高可用（脑裂）**：3 节点奇数 + quorum（>50% 即 ≥2 在线）选主，天然防脑裂。只要**不同时停 ≥2 台**都在安全区；跌破 quorum 集群停服务、主分片不可写（不丢数据，恢复 online 自动回归）。

**运维要点**：
- 单节点维护：逐台 `pkill -F pid` → 维护 → `bin/elasticsearch -d -p pid`，一次只停一台
- 曾异常时 `pid` 文件残留致启动报错：先 `rm -f pid` 再启
